# JBTD Kit

## Разработка, ориентированная на задачи пользователей

**Job-Driven Development для команд разработки**

*Проект завершен и готов к использованию*

---

## 🎯 Проблема

### Традиционная разработка фокусируется на функциях, а не на пользователях

- ❌ "Нужно добавить систему уведомлений"
- ❌ "Построить дашборд с графиками"
- ❌ "Реализовать экспорт в PDF"

### Результат:
- Избыточная инженерия без четкой цели
- Функции, которые никто не использует
- Сложность растет, ценность нет

---

## 💡 Решение: JBTD Kit

### Начинаем с понимания задачи пользователя

✅ **Когда** получаю срочное обновление
✅ **Я хочу** узнать об этом немедленно
✅ **Чтобы** быстро среагировать

### Задача → Решение → Код
```
Определение задачи (job.md)
    ↓
Техническое решение (solution.md)
    ↓
Реализация через AI-агентов
```

---

## 🧠 Философия: "Задачи являются исполняемыми"

### Основные принципы

1. **Задача = источник истины**
   - Код генерируется для выполнения задачи
   - Не функция → задача, а задача → решение

2. **Простота через цель**
   - Служит задаче? → Оставляем
   - Не служит? → Удаляем

3. **Измеримый успех**
   - Успех = задача выполнена
   - Не "функция выпущена", а "пользователь достиг цели"

## 🔄 Рабочий процесс (7 фаз)

| Фаза | Команда | Цель |
|------|---------|------|
| 1. Constitution | `/jbtd.constitution` | Принципы проекта |
| 2. **Identify** | `/jbtd.identify` | Определить задачу |
| 3. Clarify | `/jbtd.clarify` | Уточнить детали |
| 4. **Solution** | `/jbtd.solution` | Спроектировать решение |
| 5. Analyze | `/jbtd.analyze` | Валидировать |
| 6. **Tasks** | `/jbtd.tasks` | Разбить на задачи |
| 7. **Implement** | `/jbtd.implement` | Реализовать |

*Жирным выделены обязательные фазы*

## 🚀 Ключевые возможности

### CLI инструмент + AI интеграция

```bash
# Инициализация проекта
job init мой-проект --ai claude

# Начало работы
/jbtd.identify      # Определяем задачу пользователя
/jbtd.solution      # Проектируем решение
/jbtd.implement     # AI генерирует код
```

## 💼 Примеры использования

### Пример 1: Инструмент разработчика

**Задача:**
> **Когда** отлаживаю баг в продакшене
> **Я хочу** видеть логи и метрики вместе
> **Чтобы** быстро найти причину

**Решение:** Единый дашборд вместо 2 отдельных инструментов

---

### Пример 2: Онбординг пользователей

**Задача:**
> **Когда** начинаю работу с новым инструментом
> **Я хочу** сделать первую полезную задачу быстро
> **Чтобы** увидеть ценность до изучения деталей

**Решение:** Пропустить длинные туториалы, сразу к делу
